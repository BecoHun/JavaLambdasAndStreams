1.
Which two of the following functional interface declarations are correct?
1.
@FunctionalInterface
interface Action {
    void execute();
    default void refresh(){}
}
2.
@FunctionalInterface
interface Action {
    void execute();
    default void refresh();
}
3.
@FunctionalInterface
interface Action {
    void execute();
    static void refresh(){}
}
4.
@FunctionalInterface
interface Action {
    void execute();
    void refresh(){}
}
1 and 3
Only #1 and #3 are syntactically correct. #2 contains an incorrect declaration of a default method, and #4 contains two abstract methods.

2.
Which of the following method declarations can be used independently in a functional interface? 
private static void method(){}
void method();
The members of an interface cannot be protected. An interface's abstract methods cannot have a body.

3.
What independent changes are needed to make the declaration of the functional interface correct?
@FunctionalInterface
interface A {
    void methA();
    public abstract void methB();
}
Delete declaration methA
Delete declaration methB
Deleting one of these methods yields the correct syntax for the functional interface. 
Adding the keyword static before any of them will cause a compilation error because static methods in interfaces should have bodies.

5.
Which two of the following implementations of a functional interface are correct?
@FunctionalInterface
interface Action {
    void doAction(int num);
}
Action action = i -> System.out.println(i);
Action action = (int i) -> System.out.println(i);
That’s right! The other two options are incorrect. 
The option "Action action = Integer i -> System.out.println(i);" does not pass the syntax check. 
The option "Action action = (Integer i) -> System.out.println(i);" has the Incompatible parameter type–expected int but found Integer.

8.
Which of the following implementations of the Consumer interface is correct?
List<Integer> ints = new ArrayList<>();
    Consumer<List<Integer>> consumer = o -> ints.add(3);
The Consumer interface describes a functionality that takes a parameter, performs a useful task, and returns nothing. 
All other cases specify functionality with no side effects, generally making them useless.

Function<String, Person> stringToPerson = Person::new;

10.
Which of the following uses of a method reference is correct?
class FunctionHolder {
    public double function(final int a, boolean b) {
        return 0; 
    } 
} 
@FunctionalInterface 
interface FirstInterface <T, U, R> {
    R function(T firstArgument, U secondArgument); 
} 
FunctionHolder holder = new FunctionHolder();
FirstInterface<Integer, Boolean, Double> first = holder::function;
Yes, this is the correct parameterization for achieving covariance with the referenced method.

12.

Consumer<Integer> consumer = n -> n += x[0]+=n;
You cannot reassign the value of a captured variable, but you can change the state of the object referenced.
